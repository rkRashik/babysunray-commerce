# Admin panel

**Status:** Draft — Founder Review
**Purpose:** The screens of the private admin panel, their permissions, and how every page and form is protected.

A functional internal area at `/admin` (`src/app/admin`), built with the Next.js App Router and Tailwind CSS. In the code it is called BabySunRay Admin and its single role is `owner`. It wears the First Light design ([design system](../design/storefront-design-system.md)): a cocoa sidebar grouped by the work it serves, daily pages first, with the occasional Shop and Settings groups folded unless the current page is in them (on a phone, a bottom bar with Dashboard, Orders, Products and a Menu of every page), status words in toned pills, the main action of a page or form in amber. When the connected database carries the founder's staging marker (`src/app/admin/_lib/staging.ts`: the same `isStagingDatabase` check acceptance uses, read from the database itself; no environment variable or setting can turn it on, and an unreadable database shows no notice), every page shows a "Test database (staging)" notice so test orders and figures cannot be taken for real sales.

## How it is protected

- Sign-in and sign-out call Better Auth's own `/api/auth` endpoints from the browser, so its origin check and sign-in rate limit apply. The session is the HttpOnly cookie; page scripts never see a token, and a Bearer token does not open the admin panel.
- Every page and every Server Action checks the session and permission on the server itself (`src/app/admin/_lib/session.ts`); a layout check alone is never relied on. Server Actions call the same idempotent operations as the API directly, never `/api/v1`. The actor is always the signed-in user; form fields cannot name one. Next.js checks the origin of Server Action requests.
- Each form carries a server-generated idempotency key, so a double-click or resubmission records one change; the submit button is disabled while saving. Edit forms carry the version they were loaded from, so a stale second tab gets a "reload" message and keeps what was typed. Prices are typed in Taka (up to two decimals) and stored exactly as integer paisa (`src/modules/money.ts`).
- Errors shown are the services' safe messages or a generic one; raw errors and SQL never reach the page.
- Every `/admin` response sends `Content-Security-Policy: frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Robots-Tag: noindex, nofollow`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin` (`next.config.ts`); pages are dynamic, so they are not cached.

Not built: changing a slug or SKU, reactivating a variant, un-archiving a product, publication, a photo API, expenses and supplier records, courier statement reconciliation, and export endpoints in `/api/v1`. Tested with fictional accounts: integration tests of the Server Actions and real-browser tests of sign-in, access control, the catalogue, stock, order and preview flows, stale edits, double submission, lost responses, keyboard use and phone-sized screens ([testing.md](../testing.md)).
